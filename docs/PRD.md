# Step-into-A-World｜產品規格（PRD v0.5）

版本：PRD v0.5 · 2026-10-27（America/Vancouver）
用途：ASUS UGen AI League 2026 · Creator AI 主題 × Lightning 輕量運算組 × 線上組 · Stage I 提案
狀態：收斂定案版 v0.5（專案名統一＋即時觀測機制明確化）。本文定方向、定產品、定繳件範圍；開發按 Stage I 提案 → Stage II 原型推進。

> **讓靜態網站活起來的即時觀測工具框架——每一次觀察，都為同一個場地生成一支新的影片：符合該領域的生物隨機出現，氣候、時間隨時變化；不再是所有人看同一支預先生成的影片。**

## 0. 定位

- **專案＝ Step-into-A-World**：靜態網站 → 即時動態世界的工具框架，為本活動而建的全新專案。
- **示範場域一＝ K's Hunting Log（新巴比倫 ZERO 狩獵日誌）**：第一個套用框架的靜態網站；現有 journey 頁為初期模擬與 Stage I 切片素材。**K 網站本身不是提案作品。**
- **時程分工**：Stage I 交企劃＋概念架構＋初期模擬（規則明言：不限指定硬體，可先以筆記型電腦、SBC 或虛擬主機進行初期模擬與驗證）；Stage II 才做原型開發＋軟硬體整合＋效能驗證。
- **隊伍**：個人參賽（1 人）。

## 1. 問題

1. 靜態網站的世界是死的。圖片預先生成，看完就固定不變，讀者無法知道「現在」發生什麼。
2. 預生成成本高、更新慢。世界一改就要整批重算重出圖，創作者跟不上世界的變化。
3. 沒有即時觀測入口。讀者只能讀過去的日誌，不能看著世界正在發生。
4. 舊站沒有活起來的方法。每個站想變動態都要重做一套系統，沒有可重用的框架。

## 2. 產品定義

### 2.1 輸入：靜態網站

一包現成的東西，任何靜態網站都能對照提供：

- 頁面與預生成圖片：現有網站的全部內容。
- 正典資料：領域地理、物種圖鑑、旅程路線、田野日誌、世界狀態。

### 2.2 處理：框架管線

1. **解析與建模**：讀靜態網站內容，建立世界模型（地形、棲地、物種、路線、狀態），每筆資料回指來源。
2. **即時生成**：每一次觀察觸發一次生成，在邊緣裝置上即時算出影片——符合該領域的生物隨機出現（例如強風來時收翼、高空風窗巡飛），氣候、時間隨時變化；不預渲染、不重播舊檔。
3. **即時觀測**：瀏覽器開啟就是一次新的觀察——同一場地，每個人每次開啟都看到不同的影片；走到地點可打開當天的田野筆記；禁線有實質意義（停在禁線外、折返），不是貼圖。
4. **狀態回寫**：事件改變狀態（足跡留存、路線開閉、物種移動），下一輪觀測從更新後的狀態出發。
5. **發布驗證**：正典、素材、路由、語系四道檢查通過才上線；擴寫內容標示 EXPANSION，須符合棲地、生態鏈與既有設定；框架不改寫作者主線。

**通用性**：同一套框架，換一個靜態網站就讓另一個站活起來；資料驅動，不寫站點專用邏輯。

### 2.3 輸出：可即時觀測的動態世界

- 瀏覽器可開，不需頭戴裝置；每一次開啟都是一支新影片。
- 效能目標以 UGen300 實機量測為準。輕量運算是框架的核心約束：每次觀察的即時生成必須在 8GB、40 TOPS INT4 的邊緣裝置上跑得動——這也是硬體整合的著力點。

### 2.4 展示命題

同一個 K 場地，提案前所有人看同一支預先生成的影片，提案後每個人每次開啟都看到不同的影片（生物隨機出現、氣候時間變化）；換一個靜態網站，同一套框架讓它活起來。

## 3. 示範計畫

### 3.1 示範場域一：K's Hunting Log

- 現況：靜態站＋預生成圖；journey 頁即初期模擬（Stage I 切片素材）。
- 今晚提案直接用 https://k-hunting-log.icareu.tw/journey/ 這個網址。
- Stage II：把 journey 的即時觀測獨立成一個獨立網址（網址到時再定）；原型在 UGen300 上給雲梯讓道礦廊加上即時觀測——每次開啟生成新影片（物種隨機出現、氣候時間變化、禁線折返）。

### 3.2 示範場域二：通用性的證據

- 需求：第二個靜態網站，與 K 不同、具合法使用權，同一套框架、不改程式，讓它活起來。
- 定案：由我方撰寫一份短篇原創正典（方向初定深海熱泉觀測站，與 K 的高山霧廊完全不同；用戶指定其他題材即更換）。
- Stage I 簡報寫作驗證計畫；Stage II 實作出來給評審看。

## 4. 部署與賽道

- 主題：Creator AI（創作體驗；含即時渲染）。
- 賽道：Lightning 輕量運算組（ASUS UGen UGen300：Hailo-10H、40 TOPS INT4、8GB；晉級隊伍得一台免歸還；Stage II 在該裝置上開發、整合、驗證）。
- 組別：國際線上組（遠端評選，不用到場）。

## 5. 繳件與時程

- Stage I（今晚）：英文提案簡報正文 20 頁以內（附錄不計），須含情境背景與問題定義、解決方案（工具／技術／方法論）、軟硬體架構設計與系統規劃、預期效益與產出成果、參考文獻與 GitHub 原始碼專案連結；3 分鐘以內英文影片（初期模擬畫面＋概念架構），上傳 YouTube 設「知道連結者可觀看」，繳件時提供網址。截止：台北 10/28 17:00＝溫哥華 10/28 凌晨 02:00。
- Stage II（若入圍）：11/02 公布入圍（輕量運算組線上組前 5 名晉級）；11/06–12/04 開發期（UGen300 原型＋軟硬體整合＋效能驗證）；線上組決賽 12/04 提交截止（英文決賽簡報、10 分鐘以內影片、完整 GitHub 儲存庫含系統架構圖、README、模型資訊及效能驗證資料）；12/19 線上組結果與實體組決賽同步公布。

## 6. 評分對照（規則權重）

- 創新與創意 30%：靜態 → 即時，預生成 → 即時運算；不是再一個 3D 世界生成器。
- 商業潛力與可行性 35%：框架授權＋代建服務；灘頭＝IP 持有者與獨立互動敘事團隊，新巴比倫為第一個落地（第一個客戶兼證據）。
- 實用價值 25%：舊站不用重做就能活起來。
- 敘事表達與展現力 10%：從讀日誌變成看世界正在發生；影片按旅程路線拍。
- 另：輕量運算組最佳硬體整合獎（$1,500）：在 Hailo-10H 上跑即時世界觀測。
