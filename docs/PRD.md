# Step-in-A-World｜產品規格（PRD v0.2）

版本：PRD v0.2 · 2026-10-27（America/Vancouver）
用途：ASUS UGen AI League 2026 · Creator AI 主題 × Thunderstorm 賽道 × 線上組 · Stage I 提案
狀態：討論稿 v0.2。本文定方向、定產品、定繳件範圍；開發按 Stage I 提案 → Stage II 實作推進。

> **給它任何一個故事世界的正典資料，它就生成一個可以第一人稱走進去、會記得你來過的 3D 世界。**

## 0. 定位

- **專案＝ Step-in-A-World**：故事正典 → 可步行 3D 世界的通用引擎，為本活動而建的全新專案。
- **示範世界一＝ K's Hunting Log（新巴比倫 ZERO 狩獵日誌）**：第一份餵給引擎的正典資料。

## 1. 問題

1. 故事世界只能讀，不能走進去。讀者讀完日誌就離開，沒辦法親自站在那個棲地裡。
2. 生成內容沒有狀態、會漂移。今天畫的物種明天就忘了，設定前後不一致，昨天的事件不影響今天。
3. 創作者無法持續產出。世界出版後就死了，沒有一條讓世界每天長出新內容又不偏離正典的迴路。
4. 讀者沒有長期入口。沒有「昨天走到哪、今天能走到哪」的連續體驗。

## 2. 產品定義

### 2.1 輸入：正典資料包（Canon Package）

格式中立的一包資料，任何故事都能對照填寫：

- 領域地理：地形、氣候、水文、植被帶、海拔與禁區。
- 物種圖鑑：外觀、行為、棲地、風險等級、與其他物種的關係。
- 旅程路線：已走過的路徑、節點、禁線與折返點。
- 田野日誌：日期、位置、觀察、證據等級（確定／推測／未知）。
- 世界狀態：上一輪結束後的狀態快照（足跡、路線開閉、物種位置）。

### 2.2 處理：引擎管線

1. **匯入與建模**：讀正典資料包，建立世界模型（地形、棲地、物種、路線、狀態），每筆資料回指來源。
2. **3D 場景生成**：由世界模型生成地形、植被、物種外觀、光霧與氛圍，全部來自正典資料。
3. **Agent 生態驅動**：物種按棲地條件行動（例如強風來時收翼、高空風窗巡飛），不是擺設；行為結果寫回世界狀態。
4. **狀態回寫**：事件改變狀態（足跡留存、路線開閉、物種移動），下一輪從更新後的狀態出發。
5. **發布驗證**：正典、素材、路由、語系四道檢查通過才上線；擴寫內容標示 EXPANSION，須符合棲地、生態鏈與既有設定；引擎不改寫作者主線。
6. **上線與回報**：輸出可步行的 3D 世界（瀏覽器可開）＋世界狀態檔；營運狀態（位置、版本、下一輪）可讀回。

**通用性**：同一套管線，換一份正典資料就換一個世界；資料驅動，不寫故事專用邏輯。正典沒寫的，留空或由作者補。

### 2.3 輸出：可步行的 3D 世界

- 第一人稱步行，瀏覽器可開，不需頭戴裝置。
- 走到地點可打開當天的田野筆記；禁線有實質意義（例如停在禁線外、把前進箭頭改成折返），不是貼圖。
- 昨天的足跡、草籽、掌距今天還在原地；世界記得你來過。
- 效能與畫質目標以 Thunderstorm 實機量測為準。

### 2.4 展示命題

更換正典資料包，不更換程式，同一套引擎產出地貌、生態、物種、氛圍都不同的世界；且後續探索必須讀取前一天的狀態。

## 3. 示範計畫

### 3.1 示範世界一：K's Hunting Log

- 輸入規模：14 個領域；本週旅程 FK-W013 雲梯讓道礦廊；五日物種（銅脈石地衣、霧階摺翅螽斯、晶背羊駝、雷索神鷹、霧角美洲豹）與五日田野日誌。
- 產出：雲梯讓道礦廊可步行場景。路線：索道支架 → 銅脈霧岩階 → 摺翅草帶 → 晶背草坡 → 雷索高空風窗 → 霧角禁入石階；終點重演日誌裡的抉擇（停在禁線外、折返）。

### 3.2 示範世界二：通用性的證據

- 需求：一份與 K 完全不同的短篇正典（不同地貌、不同生態、不同敘事語氣），同一套引擎、不改程式，產出不同世界。
- Stage I 簡報寫作驗證計畫；Stage II 實作出來給評審看。

## 4. 部署與賽道

- 主題：Creator AI（創作體驗；含即時渲染）。
- 賽道：Thunderstorm（ASUS UGen Intel Arc Pro B70 32GB；高算力、Agentic AI 工作負載；Stage II 由主辦單位提供虛擬主機，透過 SDV 系統開發與驗證）。
- 組別：國際線上組（遠端評選，不用到場）。
- Stage II 計畫：把引擎部署進 SDV，在裡面跑示範世界一與示範世界二；決賽影片呈現 SDV 實際操作與驗證畫面。

## 5. 繳件與時程

- Stage I（今晚）：英文提案簡報正文 20 頁以內（附錄不計），須含情境背景與問題定義、解決方案（工具／技術／方法論）、軟硬體架構設計與系統規劃、預期效益與產出成果、參考文獻與 GitHub 原始碼專案連結；3 分鐘以內英文實機展演影片，上傳 YouTube 設「知道連結者可觀看」，繳件時提供網址。截止：台北 10/28 17:00＝溫哥華 10/28 凌晨 02:00。
- Stage II（若入圍）：11/02 公布入圍；11/06–12/04 開發期；線上組決賽 12/04 提交截止（英文決賽簡報、10 分鐘以內影片、完整 GitHub 儲存庫含系統架構圖、README、模型資訊及效能驗證資料）；12/19 線上組結果與實體組決賽同步公布。

## 6. 評分對照（規則權重）

- 創新與創意 30%：通用引擎＋狀態連續的活世界，不是單一場景 demo。
- 商業潛力與可行性 35%：每個 IP 都能擁有可走進去的第二生命；Stage II 在 SDV 上的實機驗證是可行性證據。
- 實用價值 25%：創作者持續產出、讀者從閱讀變成造訪。
- 敘事表達與展現力 10%：走進旅程本身就是敘事；影片按旅程路線拍。

## 7. 開放問題（收斂用）

1. 最小切片範圍：做不做？做哪個棲地（建議 FK-W013 其中一段）？做到什麼程度（能走＋一種生物＋開筆記）？
2. 示範世界二選哪份正典？需與 K 完全不同，且作者須擁有合法使用權。
3. 引擎 repo 公開或私有？（Stage I 簡報須附 GitHub 連結；決賽須接受程式碼抽驗。）
4. 今晚影片分鏡：引擎輸出畫面與輸入資料畫面的呈現方式。
5. 隊伍：個人參賽（1 人）或組隊？（規則允許 1–5 人。）
